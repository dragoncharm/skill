# 目的

为进一步落实产品安全的基本要求，加强研发、交付、供应链各领域产品安全治理的过程控制，特制定本产品安全红线管理规定。

# 概述

本标准定义了产品安全领域的红线要求，规定对不符合要求的过程和结果必须采取纠正措施后方可继续下一流程。本标准适用于公司所有的产品/项目及研发、交付、供应链各领域的业务单位及个人。

# 术语和定义

下列术语和定义适用于本标准。

## 产品安全红线

产品安全红线规定了浩鲸科技业务过程、产品或服务的最基本安全要求，是各业务单位开展工作过程中必须达到的标准。

## 后门

后门是指那些未公开的绕过安全性控制而获取对程序或系统访问权的程序方法。

参考：[Microsoft defines Backdoors as “A hidden entrance to a Computer system that can be used to bypass security policies”].

## 个人数据

与已识别或可识别的自然人（数据主体）相关的任何数据。可识别的自然人是指通过姓名、身份证号、定位数据、网络标识符号及特定的身体、心理、基因、精神状态、经济、文化、社会身份等识别符能够被直接或间接识别到身份的自然人。

## 安全事件

安全事件是指违反了安全政策、可接受的使用政策或标准安全实践，或者指即将发生的违规威胁。

# 角色与职责

各角色对自己职责涉及的安全问题负责。

## 产品安全委员会

- 公司产品安全工作的最高决策机构；
- 制定公司产品安全战略并保障资源，确定公司产品安全工作战略方向和目标；
- 审议产品安全规划，决策产品安全相关重大议题等。

## 产品/项目团队

各业务单位作为产品安全的第一道防线，负责按照产品安全的相关规范，交付安全的产品。

## 产品安全经理

- 协助业务单位团队负责人指导和监控产品/项目的安全红线要求的落实；
- 对产品/项目执行过程进行审核，对触犯产品安全红线的行为及时叫停，监督整改；
- 向项目组培训和宣贯产品安全红线要求；
- 配合产品安全能力中心对项目重大安全问题进行调查、分析、改进。

## 产品安全能力中心

- 对产品安全委员会负责，执行、落实、协调、跟踪产品安全委员会的决议，定期向产品安全委员会汇报公司各业务单位的安全状态和安全风险；
- 跟踪安全行业治理模型、标准的最新动态，制定适应公司的产品安全规范；
- 作为产品安全保障流程的第二道防线，对各业务单位（第一道防线）产品安全执行过程和结果进行监控、审计；
- 对触犯产品安全红线，或引发重大安全事件、或者客户投诉的行为进行调查、问责。

## 产品安全红线管理要求

任何产品/项目触犯产品安全红线时，必须及时叫停，整改完成后方可走下一流程。如不满足要求，提交产品安全委员会审批同意后方可放行，否则属违规行为，违反流程的责任单位和个人将受到相应处罚。

### 实施要求

本标准要求由各业务单位在项目运作中加以控制，执行情况由产品安全经理在过程审核中加以监督。

### 处罚要求

对违反红线要求的行为，产品安全经理报请业务主管对违规责任人加以处罚或考核（相关信息同步抄送至产品安全能力中心）；

如果产品安全能力中心进行抽查发现业务团队有触犯安全红线要求的行为，则对应的产品安全经理及业务主管需要接受处罚或考核。如产品安全能力中心抽查之前，责任单位已经发现违规行为并制定改进计划，则可以免于处罚。

如果现场逾越产品安全红线要求引发重大安全事件、客户投诉，产品安全能力中心将依据本产品安全红线要求对违规业务单位及个人进行处罚，单位领导进行问责。

# 产品安全红线问题处理

## 基本流程

发现产品/项目执行过程中存在触犯产品安全红线要求情形，产品安全经理需立即叫停触犯红线要求的行为或交付流程，并及时发起产品安全红线问题整改流程。责任单位、个人按照整改要求提供具体的治理措施并进行整改，最后由产品安全经理根据整改最终状态进行评估，给出是否走下一流程的判定结论，相关效果评估依据和结果要发送邮件至产品安全能力中心进行报备处理。

处理触犯安全红线行为的流程基本为叫停、整改、效果评估。根据行为造成的后果或潜在的影响，对内处理方式有通报、警告、考核扣分、罚款、调岗免职等。

## 具体实施

### 禁止产品中存在后门

【红线详解】：系统不允许任何人通过后门获得系统访问权限，系统访问能力必须在用户手册中说明。

【触发时间】：产品生命周期的任何阶段。

【触发场景】：客户、第三方机构、独立安全测评及外部白帽发现产品中存在未公开的绕过安全性控制而获取对程序或系统访问权的程序方法场景。

【触发行动】：叫停产品当前流程，清除后门功能，并进行责任回溯。

【备注说明】：主要针对产品主动预置的客户不熟悉的功能场景。

### 禁止交付的产品中存在中危和高危安全漏洞

【红线详解】：交付版本中禁止存在代码自动化扫描工具检查发现并认定的高危及以上安全缺陷， 禁止存在产品安全测试或独立安全测评/审计时发现并认定的中危和高危安全漏洞。

【触发时间】：产品研发项目结项前，或合同项目版本上线前。

【触发场景】：代码自动化扫描工具发现并认定的高危及以上安全缺陷，产品安全测试或独立安全测评/审计时发并认定的中危、高危安全漏洞未完全修复。

【触发行动】：叫停产品研发项目结项流程，或合同项目的版本对外发布流程，修复所有代码自动化扫描工具检查发现并认定的高危及以上安全缺陷，修复所有安全测试或独立安全测评/审计时发现并认定的中危、高危安全漏洞，并进行责任回溯。

【备注说明】：

- 产品安全测试的范围包括安全功能测试和安全扫描。
- 安全扫描为在《浩鲸科技产品研发安全规范》中规定的安全扫描工具和类型。
- 包含网络、操作系统安全漏洞扫描。
- 代码自动化扫描工具检查发现并认定的高危及以上安全缺陷，安全功能测试和扫描发现的中危及以上安全漏洞都属于红线要求范围。

### 禁止违规处理个人数据

【红线详解】：严格遵从数据获取“最小化”原则，禁止扩大数据收集范围，严禁在系统中记录非业务所必须的个人数据；系统对个人数据的存储、传输和处理需保证数据安全，并遵从适用国家和地区的法律和法规要求。

【触发时间】：产品生命周期的任何阶段。

【触发场景】：产品开发过程中发现存在系统记录非必须的个人数据及数据保护措施明显缺失的场景。

【触发行动】：叫停产品当前流程，对违规流程或功能进行立即治理，并进行责任回溯。

【备注说明】：个人数据相关定义见术语和定义章节。

### 禁止未经客户书面授权情况下访问客户网络和数据

【红线详解】：所有涉及访问客户网络和数据的场景，都必须获得客户的正式授权，并且授权记录必须可举证，所有未经授权的客户网络和数据访问都是违规的。

【触发时间】：外部开局、升级及操作维护阶段。

【触发场景】：现场检查发现、客户投诉、出现与未经客户授权访问客户网络和数据相关联的外部安全事件。

【触发行动】：流程叫停，立即启动整改，申请客户书面授权，对可能存在的潜在风险进行及时管控，并进行责任回溯。

【备注说明】：无。

### 禁止瞒报、拖延或忽视安全事件

【红线详解】：内外部发现的安全事件，必须及时上报公司产品安全能力中心，并及时处理，严禁瞒报、拖延或忽视安全事件的行为发生。

【触发时间】：产品生命周期的任何阶段。

【触发场景】：内外部发生安全事件。

【触发行动】：流程叫停，立即启动安全事件处理，并进行责任回溯。

【备注说明】：

1. 内部发现的安全事件或漏洞指与公司产品相关、由公司内部人员发现的产品安全事件或漏洞，来源包括第三方厂商、开源产品和自研产品。
2. 外部发现的安全事件或漏洞指与公司产品相关、从公司外部渠道获取的安全事件或漏洞，来源包括但不限于外部漏洞平台、供应商、客户、CERT 组织、研究团队或个人。
