# 设计文档模板

用户批准方案时（任何代码变更之前），把设计文档写为 `<单号>_<标题>_开发方案.md`。标题做文件系统安全处理：`/ \ : * ? " < > |` 和换行替换为 `-`，超长标题截断；单号前缀保持完整。示例：`12012113_V9L-哥伦比亚ETB-月账单DIAN集成优化-BM拆单_开发方案.md`。

创建时用批准的方案填写第一至五节；第六至九节以「待实施后填写」占位，随对应阶段完成而回填。全程更新这同一份文件——绝不为单子创建第二份文档。

````markdown
# <单号> <标题> — 开发方案

- 文档更新时间：<每次更新刷新>
- 处理模式：脚本单 / 大功能单 / 小bug单
- 进度：方案已批准 / 实施中 / 检查完成 / 收尾完成

## 一、单据信息

- 单号：<…>
- 标题：<…>
- 当前状态 / 分支版本 / 应用模块：<…>
- 需求复述：<按主流程识别当前有效决定后的理解>
- 关键评论（改变过方向的，按时间正序）：
  - <时间> <人>：<内容>

## 二、影响面定位

- 入口：<…>
- 调用链：<…>
- 数据库表：<…>
- 配置：<…>
- 相似实现：<…>

## 三、修改方案

（大功能单/小bug单：设计说明 + 涉及文件清单，每个文件标注修改/新增/删除；
脚本单：以下三段脚本全文）

### 3.1 执行脚本
```sql
-- …
```
### 3.2 验证脚本
```sql
-- 执行前：…
-- 执行后：…
```
### 3.3 回滚脚本
```sql
-- …
```

## 四、风险分析

- 兼容性：<…>
- 事务：<…>
- 缓存：<…>
- 空值：<…>
- 并发：<…>
- 回归：<…>

## 五、测试方案

- 单元测试：<…>
- 接口验证：<…>
- 回归场景：<…>
- SQL/数据验证：<…>
- 边界矩阵：<复用已选定的行为、关键边界和回归用例；需要提示时参考 closing-documents.md；未执行项明确标注>

## 六、实施记录（待实施后填写）

- 实施步骤与时间：<阶段完成时更新>
- 实际变更文件清单：<…>
- 与方案的偏差及原因：<…>

## 七、规范检查记录（待实施后填写）

- 依据文档（apply-iwhalecloud-dev-standards 引用的具体规范文档/条目）：<…>
- 复查结论与修复项：<…>

## 八、静态检查记录（待实施后填写）

- 工具与结果：<列出实际适用工具及结果；SQL 规范审查与工具扫描分开记录>
- 发现问题与修复：<…>
- 未运行的检查及原因：<…>

## 九、自测说明与影响说明草稿（待实施后填写）

### 自测说明（草稿）
<按 closing-documents.md 的结构，从第五节边界矩阵逐项回填实际结果、证据和状态；适用但未执行的边界必须保留并说明原因>

### 影响说明（草稿）
- 修改内容：<中文> / <English>
- 业务影响：<中文> / <English>
- 其他项目影响：<中文> / <English>
````

脚本单场景下，这份文档就是脚本交付物的家：3.1–3.3 节承载完整脚本，第六节记录实际执行序列和结果（执行前验证查询 → 执行脚本 → 执行后验证查询）——如果用户在会话期间执行了的话。
